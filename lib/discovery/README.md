# Creative discovery activation and evidence

This slice never makes paid calls unless **both** server flags `DISCOVERY_PROVIDER_ACCESS_APPROVED=true` and `DISCOVERY_PAID_EXECUTION_ENABLED=true` are configured alongside `APIFY_TOKEN`. All are off/missing by default. Do not set these flags until the operator separately authorizes provider access and paid execution; possession of a token is insufficient. No live configuration was changed during implementation.

Optional visual analysis separately requires `DISCOVERY_VISUAL_ANALYSIS_ENABLED=true`, `DISCOVERY_ANALYSIS_TRANSFER_APPROVED=true`, and existing `OPENAI_API_KEY`, plus per-action confirmation of paid analysis/image transfer. It uses existing `OPENAI_ANALYSIS_MODEL` (default `gpt-6-luna`), existing provider telemetry and the REFERENCE_CLASSIFICATION quota. Search and import never invoke it. The structured-output adapter shares the application's Responses API architecture; bounded output is controlled enums only. Model/date/image SHA-256 are persisted with every inference. Reserved or unknown attempts cannot be silently retried. Visual evidence and attempt identity are bound to the image byte hash. Replacing bytes clears stale evidence/attempt state; a prior in-flight completion or failure cannot overwrite the new image state. Reacquiring identical bytes preserves valid analysis.

The actor is fixed to `apify/facebook-ads-scraper` (API slug `apify~facebook-ads-scraper`). One keyword URL is submitted, with `resultsLimit` default 10 / application maximum 100, no page-about or per-ad enrichment. The actor's limit is **per URL**; it has no documented input maximum on the official schema. Missing limits can request as many results as possible, so this implementation always supplies one. Async submission uses POST `/v2/acts/{actor}/runs`, then explicit GET `/v2/actor-runs/{id}` and bounded GET `/v2/datasets/{id}/items`. It never retries submissions automatically. Ambiguous submissions require checking the provider console before another run. Run receipts and candidate provenance are stored before reference registration.

Official sources checked 2026-10-15:

Output is conditional; example fields include ad archive ID, snapshot image/card URLs, copy, dates, status, and often null spend/reach. Availability and pricing may change. This code does not interpret provider reach/spend as TRA performance.
- [Exact actor input schema](https://apify.com/apify/facebook-ads-scraper/input-schema): `startUrls`, `resultsLimit`, `includeAboutPage`, `isDetailsPerAd`, and URL-based filters. This is the historical actor, not similarly named community actors.
- [Apify submit API](https://docs.apify.com/api/v2/actors-runs-post), [status API](https://docs.apify.com/api/v2/actor-run-get), [dataset API](https://docs.apify.com/api/v2/dataset-items-get).
- [OpenAI Responses request fields](https://developers.openai.com/api/reference/resources/responses/methods/create) and [structured output schema](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), cross-checked against existing layout-analysis code before implementing the disabled visual adapter.

The official Ad Library API needs separate coverage/access evaluation; this implementation does not assume it covers all US commercial ads.

## Safety and practical limitations

- Every endpoint uses `getOperatorAccess`; user scope comes from the authenticated Clerk user ID, never request fields. Conditional artifact writes use a SHA-256 operator namespace and discovery/v1 keys. The existing artifact adapter places R2 keys under its video-intelligence prefix; discovery keys remain distinct and never touch creative indexes. Local storage uses `.runtime/discovery`.
- Provider image URLs never come from import request fields. Only immutable candidates from that operator's stored session can be selected. Download supports HTTPS fbcdn.net hosts only, checks DNS at connection time, validates every redirect, and enforces a 20-second timeout, streamed upload-byte cap, declared image MIME and magic. A manual image upload is available on failure and is recorded as operator-linked, not independently matched.
- Imported files use existing private media delivery and the layout-reference library. Automatic classification is absent; the category is an explicitly unclassified fallback. Imported layouts do not approve identities, claims, or proof. Shared reference-library mutations now use conditional R2 writes and bounded conflict retries in the integrated workspace candidate; this feature-only branch relies on that integration before concurrent imports are considered safe. A failed registration can be retried with the already saved media ID. Receipts are revalidated before reuse; ordinary library deletion triggers reacquisition or an honest failure, and an explicit manual replacement is honored.
- Search deduplication uses canonical image URLs excluding signed query strings. At selected import, normalized RGBA pixel SHA-256 deduplicates identical images across encodings/URLs/sessions within the authenticated operator namespace; source-byte SHA-256 is also recorded. Conditional receipts retain one media object; uncertain writes never delete potentially referenced media. A bounded 500-image operator catalog flags possible dHash visual variants (64-bit distance <=6, comparable aspect), never a guaranteed duplicate or performance signal. Preview/import/explicit analysis fingerprint only already fetched images, with a 16-million decoded-pixel cap; no bulk fetching solely for dedupe. Uninspected visual similarity is unknown. Copy-token Jaccard similarity is separately labeled copy-only. Alternate ad source links are retained. Ranking uses copy matches, optional tax context, advertiser diversity, and near-copy penalties. Neither brand size nor activity duration affects score.
- Layout and human presence remain unknown until explicit visual inference or manual source review. Optional visual inference uses controlled layout/offer/angle/human-presence labels; labels remain unverified model interpretation. The operator can filter reviewed patterns by those labels. No embeddings, performance prediction, buying, or publishing exists. Feedback is optional, private approve/reject judgment; caller-supplied financial numbers are ignored. Account performance/attribution is unavailable until authoritative account data and links exist.
- Image previews use an authenticated same-origin endpoint with private/no-store responses and the same stored-candidate CDN/DNS/byte/type boundary; no central CSP expansion is needed. Fictional sample images are never fetched.
- Fictional sample rows make no provider/media requests and cannot be imported. Session recovery stores only the opaque session ID in browser sessionStorage; authorization is rechecked server-side. Refresh is explicit rather than background polling. Supported formats are static images/card images; videos are skipped. Unsupported CDN rows are excluded, and an empty dataset is reported honestly.

## Historical PR13 findings

Inspected exact historical commit `32e6119fec64ff3bf6535df31ad3556b612faeea` via `git show`; never merged. Its route had no operator check, immediately downloaded/imported candidates, accepted arbitrary remote image URLs with implicit redirects, buffered before its actual-length check, automatically paid for tax filtering/classification whenever an OpenAI key existed, and discarded non-tax creative rather than offering transferable inspiration. Its discovery code used seven tax searches with per-search limits, exact ad-ID/image-URL deduplication only, and a final 30-candidate slice. It did not preserve provider run IDs, offer explicit review/selection, provide diversified rankings, or distinguish provider observations from verified business performance. The replacement addresses those concrete issues within the limitations above.
