# Dedicated read-only recovery build

This branch is an emergency fallback candidate based on the previous Production code, not a normal feature release. Do not merge it during the normal staging release. `next.config.ts` compiles `TRA_RECOVERY_READ_ONLY=true` into the build; no credential or environment edit is needed to make this candidate read-only.

The entry workspace shows saved images and copy only. The normal operator checks remain on every permitted API read. Proxy admission permits only GET/HEAD on `/api/creatives` and validated `/api/media/files/media_*.{png,jpg,jpeg,webp,mp4}` paths; every other application API request is rejected before a handler can advance work or invoke a provider. Creative storage mutation functions independently refuse writes.

The previous Production parser rejects newer routing, planning and logo provenance. In this dedicated recovery mode, the reader projects only familiar display fields before legacy validation. It does not rewrite the index. Rich provenance, selected frames, portfolio/checkpoint state and original media stay in storage unchanged. They become available again through the reviewed normal release. No schema downgrade, snapshot restore or data migration is part of recovery.

Use the exact CI-tested and independently reviewed recovery commit to make a **fresh Production-target build with the existing Production configuration**, after explicit emergency deployment authorization. Never promote a Preview artifact with Preview credentials. This candidate is an on-demand compatible recovery source; until a Production build is actually prepared, it is not a one-click Vercel rollback target. Keep the ordinary reviewed release and all Git histories intact. Redeploy a compatible reviewed normal release to restore editing/generation; do not restore an old index over newer work.

This covers application-code failure without relying on the old parser and prevents further server-side writes during recovery. It is not a media or metadata backup. Object deletion, corruption, expired provider assets, incorrect bucket binding or lost credentials require separate recovery coverage. Production/default Preview destinations and existing replication/backup retention must be verified independently. Do not claim that a creative-index snapshot covers videos, images, review state, portfolios or future writes.
